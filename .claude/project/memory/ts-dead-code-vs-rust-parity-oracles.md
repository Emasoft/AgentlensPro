# ts-dead-code-vs-rust-parity-oracles


^ATOM-1PX5-NXV9 [desc: "a TS file with no bundle entry can still be a live rust-core parity oracle, imported by gen-*.mjs fixture generators", keywords: dead_code unused_TS_file safe_to_delete not_in_bundle esbuild_metafile reachability_pass rust-core_parity_oracle gen-*.mjs fixture_generator import_closure import_type bundle-only_reachability dead_module_set parity_suite rust_port_pin, trdd: TRDD-4BZPAQWM, ocd: 2026-09-24, lmd: 2026-09-24]
A TS module absent from every esbuild bundle metafile is NOT necessarily dead code. 46 of the modules a bundle-only reachability pass flagged as dead were required directly by rust-core/**/tests/fixtures/gen-*.mjs (via out/test/<module>.js) — these generators are the parity oracles that pin the Rust port's output against the TypeScript original. With their import closure (including `import type`) unioned in, 56 of the 89 files a bundle-only pass flagged as dead were actually live, leaving the real dead count at 33. A pass keyed on the three esbuild bundles alone (standalone/cli.js, media/dashboard.js, media/sidebar.js) called 89 files dead before that correction. Evidence: reports/4BZPAQWM/20260924_104703+0200-dead-module-set.md. [^1]


^ATOM-8AIV-7BUZ [desc: "a byte-stable gen-*.mjs regenerate after a TS change means out/test is stale, not that the fixture is correct: run tsc -p tsconfig.test.json first", keywords: gen-*.mjs_shows_no_diff byte-stable_fixture parity_test_fails_after_TS_change stale_out/test regenerate_fixture tsc_-p_tsconfig.test.json_before_gen_script compiled_oracle_stale fixture_generator_imports_out/test rust_parity_test_red_with_no_fixture_diff clean_regenerate_is_suspicious fixture_regeneration_order, ocd: 2026-09-24, lmd: 2026-09-24]
A regenerate of a rust-core parity fixture (tests/fixtures/gen-*.mjs) is evidence about a TypeScript change only AFTER a fresh npx tsc -p tsconfig.test.json compile — before that, both a byte-stable and a changed regenerate result are meaningless, because the generators import the compiled oracle from out/test/, and a stale out/test/ makes the regenerate reflect the OLD TypeScript behavior regardless of what the source now says. A TS change that does not touch a fixture's inputs is legitimately byte-stable on its own; the failure mode is only in trusting a regenerate's result (stable OR changed) without first confirming the compile is current. Do always run npx tsc -p tsconfig.test.json BEFORE any gen-*.mjs regeneration. Evidence: reports/cc-alignment/20260924_183512+0200-I9-main-verify.md.
