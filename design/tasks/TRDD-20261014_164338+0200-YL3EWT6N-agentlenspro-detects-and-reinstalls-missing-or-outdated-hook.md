P1 NEW PURE MODULE src/cli/surfaceStamp.ts (no fs): readSurfaceStamp(text) returns the version of the line # agentlenspro-version: X inside the first frontmatter block, else null (it never throws: installed files are user-editable). compareStampVersions(a, b) compares X.Y.Z numerically and orders a prerelease below its release. It is a NEW name on purpose: src/loadedPluginVersions.ts already exports compareVersions, read by the main agent, and that one orders 2.34.0-rc.1 above 2.34.0 (it parses 0-rc as 0 and then finds a fourth part); it is not reused and not changed. surfaceVerdict(input) returns one of install, current, overwrite, keep-newer, keep-edited.
P2 WHAT IS COMPARED: the stamp of the installed copy against the stamp INSIDE THE SHIPPED FILE (for a skill: the two SKILL.md files), not against package.json, because in a checkout the two can differ between a version bump and the next stamp write. VERDICT TABLE, tested in this order: installed copy absent, install. Same content, current. Shipped file has no stamp, overwrite (the rule of today; this keeps every fixture with unstamped files behaving as before). Installed copy has no stamp or an unreadable one, overwrite. Installed stamp older, overwrite. Installed stamp newer, keep-newer. Same stamp and different content: overwrite in a git checkout (a src folder beside the package root), keep-edited in a release. A skill gets ONE verdict for its whole tree; same content means the tree hash over the shipped file list is equal.
P3 BACKUP, UNCONDITIONAL (review finding): every existing file that is about to be replaced is copied first, whatever the verdict, so an install over a partial skill tree also keeps the old bytes. Target: <backupRoot>/<UTC time>-<pid>/agents/<name>.md or /skills/<name>/<relative path>, one folder per process run, created at the first backup. A failed copy throws and nothing is replaced. The backup is a COPY of the replaced files, not a move of the tree (departure from plan revision 3: a move would remove files the user added to a skill folder, which installSkill promises to leave). backupRoot is a new option of InstallSkillOptions with NO default: replacing an existing file without it throws. Reason: a default taken from the data dir would let a test write into the real data dir. Callers pass it: the setup step and the launch repair pass <ctx.dataDir>/surface-backups, the --install-skill path passes <dataDir()>/surface-backups (src/dataDir.ts). No purge: the folder grows by one sub-folder per run that replaces files; on a checkout that is one per edited surface per self-heal. A cap is left for a later item.
